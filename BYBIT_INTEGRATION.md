# ByBit Testnet Integration Guide

This document describes the ByBit integration for automated trading on the ByBit testnet.

## Overview

The project now includes a complete ByBit trading integration that allows automated execution of trading signals generated by the Automated Trading System.

### Key Components

1. **ByBitClient** (`bybit_client.py`) - Async HTTP client for ByBit V5 API
2. **SignalExecutor** (`signal_executor.py`) - Executes trading signals on ByBit
3. **UpdateBus** (`update_bus.py`) - Thread-safe communication for execution updates

## Setup

### 1. Create ByBit Testnet Account

1. Go to [ByBit Testnet](https://testnet.bybit.com)
2. Create an account
3. Navigate to API Management
4. Create a new API key with the following permissions:
   - **Read** - For checking positions and orders
   - **Trade** - For placing and canceling orders

### 2. Configure Secrets

1. Copy the example secrets file:
   ```bash
   cp .streamlit/secrets.toml.example .streamlit/secrets.toml
   ```

2. Edit `.streamlit/secrets.toml` with your API credentials:
   ```toml
   [bybit]
   api_key = "your_actual_api_key"
   api_secret = "your_actual_api_secret"
   testnet = true
   ```

⚠️ **WARNING**: Never commit `secrets.toml` to version control! It's already in `.gitignore`.

### 3. Run the Application

```bash
streamlit run web_ui.py
```

## Usage

### Automated Signals Tab

1. Navigate to the **🤖 Automated Signals** tab in the web UI
2. Configure your signal parameters and weights
3. Expand the **"ByBit Execution"** section
4. Enable trading by toggling **"Enable ByBit Execution"**
5. Enter your API credentials (or use secrets.toml)
6. Configure leverage and position sizing
7. Set **"Dry Run"** mode for testing (recommended initially)

### Trading Modes

#### Dry Run Mode
- Simulates trades without actual execution
- Logs intended actions to CSV
- Safe for testing strategies

#### Live Mode (Testnet)
- Executes real trades on ByBit testnet
- Uses testnet funds (not real money)
- Full order lifecycle management

### Signal Format

Signals must include the following fields:

```python
{
    "signal_id": "unique_signal_id",
    "symbol": "BTCUSDT",
    "direction": "LONG",  # or "SHORT"
    "entry_price": 50000.0,
    "take_profit": 51000.0,
    "stop_loss": 49000.0,
    "quantity": 0.001,  # Position size
    "leverage": 5  # Optional, defaults to configured value
}
```

## Security Considerations

1. **API Keys**: Store in `secrets.toml`, never in code
2. **Testnet First**: Always test on testnet before mainnet
3. **Dry Run**: Use dry run mode to validate strategies
4. **Position Limits**: Configure max position size in risk settings
5. **Kill Switch**: Disable execution immediately if issues arise

## Monitoring

### Execution Logs

Trade executions are logged to `trade_execution_log.csv` with the following columns:
- `timestamp` - Execution time (UTC)
- `signal_id` - Signal identifier
- `symbol` - Trading pair
- `direction` - LONG or SHORT
- `qty` - Position quantity
- `entry_price`, `take_profit`, `stop_loss` - Price levels
- `leverage` - Leverage used
- `status` - Execution status (filled, error, dry_run)
- `response_code` - API response code
- `latency_ms` - Execution latency
- `error_msg` - Error message if any

### Real-time Updates

The SignalExecutor publishes updates via UpdateBus:
- `EXECUTION_UPDATE` - Trade execution status
- Monitor via the UI or subscribe to the update bus

## Troubleshooting

### Common Issues

1. **"API credentials not configured"**
   - Check that API key and secret are entered correctly
   - Verify secrets.toml exists and is properly formatted

2. **"Set leverage failed"**
   - Some symbols have leverage restrictions
   - Try lower leverage values

3. **"Insufficient margin"**
   - Check testnet wallet balance
   - Reduce position size or increase leverage

4. **Asyncio errors in Streamlit**
   - Fixed by using thread-based execution
   - Report if issues persist

## API Reference

### ByBitClient Methods

- `set_leverage(symbol, leverage)` - Set trading leverage
- `place_order(...)` - Place a new order
- `cancel_order(symbol, order_id)` - Cancel an existing order
- `get_order_status(symbol, order_id)` - Check order status
- `get_position(symbol)` - Get current position
- `get_wallet_balance()` - Get account balance
- `get_open_orders(symbol)` - List open orders

### SignalExecutor Methods

- `configure(...)` - Configure executor settings
- `execute_signal(signal)` - Execute signal asynchronously
- `execute_signal_sync(signal)` - Execute signal and wait for result
- `get_position(symbol)` - Get current position for symbol
- `is_position_open(symbol)` - Check if position is open
